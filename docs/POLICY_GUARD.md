# 1~9단계 안전 정책 사본과 격리 시험

이 절차는 현재 `src/decider.mjs`의 판정 규칙, `aleph.config.json`의 `allowedRoutes`, 그리고 `supabase/migrations/` 바로 아래의 모든 DB 정책 파일을 정책으로 취급합니다. 확장자가 `.sql`이 아닌 마이그레이션 파일도 포함합니다. 저장 위치는 `.policy-guard/`이며 실제 운영 정책 파일은 읽기만 합니다.

## 1. 사본 만들기

저장소 루트에서 먼저 미리보기를 실행합니다.

```sh
node scripts/policy-guard.mjs snapshot
```

화면에서 버전/확인값, 기준 커밋, 복사 대상 전체와 파일별 SHA-256을 확인합니다. 출력된 버전값과 파일 범위가 기대한 것과 다르면 멈추고 확인합니다. 맞을 때만 같은 명령에 출력된 값을 그대로 붙입니다.

```sh
node scripts/policy-guard.mjs snapshot --confirm <미리보기의-사본-버전>
```

기존 안전 사본이 있으면 덮어쓰지 않습니다. 기존 사본을 임의로 바꾸거나 새 사본으로 대체하지 마세요. `snapshot` 완료 뒤 아래 검증을 실행합니다.

```sh
node scripts/policy-guard.mjs verify
```

`verify`는 사본의 파일 목록, 각 파일의 크기와 SHA-256, 전체 버전 해시를 검사합니다. 사본이 없거나 하나라도 빠짐·추가·변조되면 중단합니다. 현재 실제 정책 파일이 사본과 다르다는 참고 결과는 표시하지만, 어떤 파일도 복원하거나 수정하지 않습니다.

## 2. 시험용 사본에서 한 줄만 바꾸기

먼저 `verify`가 통과해야 합니다. 시험 변경은 안전 사본을 기준으로 하며, 줄 번호와 새 줄을 정한 뒤 미리보기만 실행합니다.

```sh
node scripts/policy-guard.mjs simulate --file src/decider.mjs --line <줄번호> --to "<새 규칙 한 줄>"
```

화면에 기준 사본 버전, 바뀔 파일·줄, 기존 줄과 새 줄, 격리 저장 위치, 변경 확인값이 표시됩니다. 변경 범위가 한 파일·한 줄이 아니거나 예상과 다르면 확인값을 사용하지 않습니다. 의도한 시험 변경이 맞을 때만 같은 명령에 출력된 값을 붙여 실행합니다.

```sh
node scripts/policy-guard.mjs simulate --file src/decider.mjs --line <줄번호> --to "<새 규칙 한 줄>" --confirm <미리보기의-변경-확인값>
```

기존 시험 사본이 있으면 덮어쓰지 않습니다. 여러 줄을 넣는 값, 안전 사본에 없는 파일, 경로 이탈은 거부됩니다.

## 3. 시험 정책의 차이만 보기

```sh
node scripts/policy-guard.mjs diff
```

비교 전에 안전 사본과 시험 사본의 기록된 해시·전체 파일 목록을 모두 검증합니다. 출력에는 확인된 안전 사본과 다른 줄만 표시하며, 기록상 정확히 한 파일의 한 줄 변경이 아니면 중단합니다. 사본이 없거나 해시가 맞지 않으면 `diff`도 아무 차이도 보여 주지 않고 중단합니다.

모든 명령은 `.policy-guard/` 안의 로컬 파일만 만집니다. DB에 접속하지 않고, 실제 DB의 운영 정책을 바꾸지 않습니다. 이 도구는 실제 정책 복원 기능이 아니며, 사본에서 운영 정책 파일로 되돌려 쓰는 기능도 제공하지 않습니다. 해시 검증은 변경 여부를 확인할 뿐 사본의 출처나 악성 변경 여부를 증명하는 서명은 아닙니다.

## 4. 서버 시험 정책을 안전 버전으로 되돌리기

위의 로컬 파일 도구는 서버 DB의 시험 정책을 복원하지 않습니다. Supabase `test_policy_state`의 시험 정책만 복원하는 별도 API 절차는 [시험 정책 복원 안내](POLICY_TEST_RESTORE.md)를 따르세요. 그 절차는 안전 사본 서명을 확인하고, 변경 범위를 먼저 보여 준 뒤 별도 확인이 있어야 적용합니다. 서비스 규칙과 감사 이력은 복원 대상에서 제외됩니다.

## 시험

격리된 임시 폴더에서 도구의 사본 누락·해시 불일치·미리보기·한 줄 차이·운영 파일 불변 조건을 검사합니다.

```sh
npm run test:policy-guard
```
